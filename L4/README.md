# Лабораторная работа 4. Динамическое программирование

Пошаговое управление инвестиционным портфелем методом Беллмана.
Выполнено полное задание: постановка, рекурсия, программа с выбором критерия,
восстановление оптимального плана и проверка результатов.

## Исходные данные

В начале есть ЦБ1 на 100 д.е., ЦБ2 на 800 д.е., депозит на 400 д.е.
и 600 д.е. свободных денег. Всего **1900 д.е.** Планирование состоит из трёх этапов.
Перед каждым этапом можно покупать и продавать целые пакеты:

| Актив | Размер пакета, д.е. | Комиссия | Минимальный остаток, д.е. |
| --- | --- | --- | --- |
| ЦБ1 | 25 | 4% | 30 |
| ЦБ2 | 200 | 7% | 150 |
| Депозит | 100 | 5% | 100 |

Начальные суммы, вероятности и множители взяты из приложенных Word и Excel.
Комиссии и минимумы есть в Excel, но не в текстовом описании. Они учтены.
Оригиналы сохранены в [`data/`](data).

`read_data.py` читает лист `Sheet1`: начальные суммы `J8`, `J11`, `J14`,
вероятности `K4:M6`, множители активов `K8:M16`, комиссии `D13:D15`,
минимумы `D23:D25`. Свободные 600 д.е. заданы в Word.

## Уточнения модели

В исходниках не до конца определён порядок операций. В этой реализации приняты следующие правила:

1. Пакет является фиксированной денежной суммой, равной четверти начальной стоимости.
   Например, и перед третьим этапом один пакет ЦБ1 равен 25 д.е.
2. Комиссия начисляется на сумму покупки и продажи. Продажи выполняются до покупок,
   поэтому можно использовать вырученные средства в том же этапе. Кредит запрещён.
3. Минимумы соблюдаются после сделки и после каждого исхода рынка, включая окончание планирования.
   Например, перед вторым этапом ЦБ1 должно быть не меньше `30 / 0.6 = 50` д.е.
4. Сделка выбирается до наблюдения события текущего этапа. После события выбирается продолжение,
   которое зависит только от уже известной истории.
5. Используются независимые события этапов с указанными в таблице вероятностями.
   Условные вероятности в исходных данных не заданы.
6. Свободные деньги не приносят дохода. В конце учитываются деньги и рыночная стоимость активов,
   без обязательной продажи всего портфеля и дополнительной комиссии за такую продажу.

Числовые результаты относятся именно к этой модели. Если преподаватель подразумевает
другой момент проверки минимумов или другое начисление комиссии, это меняет задачу.

## Как работает метод

Состояние `s = (x1, x2, x3, c)` содержит стоимости трёх активов и свободные средства.
Управление `k = (k1, k2, k3)` содержит целые изменения пакетов. Плюс означает покупку,
минус продажу. После сделки:

```
y[i] = x[i] + q[i]*k[i]
fee = sum(alpha[i]*q[i]*abs(k[i]))
d = c - sum(q[i]*k[i]) - fee
```

При исходе `j` состояние следующего этапа равно `(r[t,j,1]*y1, r[t,j,2]*y2, r[t,j,3]*y3, d)`.
Программа перебирает все сделки, которые соблюдают денежный баланс и минимумы во всех исходах.

В конце `V4(s) = x1 + x2 + x3 + c`. На остальных этапах:

```
V[t](s) = max по допустимым k: критерий(V[t+1](переход(s,k,j)))
доход = V[1](начальное состояние) - 1900
```

Критерий выбирается пользователем:

- **Байес**: сумма результатов исходов с их вероятностями, максимизируется ожидаемый доход.
- **Вальд**: минимум по исходам, максимизируется результат в худшем сценарии.

Значения вычисляются рекурсивно от конца к началу и сохраняются для повторного использования.
Прямой проход восстанавливает дерево решений: 1 сделка перед первым этапом,
3 возможных сделки перед вторым и 9 перед третьим. Получаются 27 конечных сценариев.
Это план с условиями, а не одна заранее известная последовательность событий.

Последний слой ускорен точным исключением невыгодных сделок. Когда условия сокращения
не выполнены, используется полный перебор. Сравнение с полным перебором включено в тесты.
Активы и денежные остатки хранятся целыми числами в миллионных долях д.е.
Численная арифметика с плавающей точкой используется для математического ожидания.

## Результаты

| План | Ожидаемый капитал | Худший капитал | Ожидаемый доход | Худший доход |
| --- | --- | --- | --- | --- |
| Байес | 2033.7038838 | 1519.76 | 133.7038838 | -380.24 |
| Вальд | 1909.2915788 | 1759.54 | 9.2915788 | -140.46 |
| Без сделок | 2015.8882088 | 1676.56 | 115.8882088 | -223.44 |

Первое действие Байеса: купить 23 пакета ЦБ1 на 575 д.е. и заплатить 23 д.е. комиссии.
После сделки `(675, 800, 400, 2)`.

Первое действие Вальда: продать 2 пакета ЦБ1 и 3 пакета ЦБ2, комиссия 44 д.е.
После сделки `(50, 200, 400, 1206)`.

Полные планы из 13 решений приведены в отчёте и в CSV. Отрицательный доход по Вальду
означает, что даже лучший план не обеспечивает положительный итог во всех сценариях.
При равных значениях возможны другие оптимальные планы.

## Запуск

```
cd L4
python -m pip install -r requirements.txt
python main.py --criterion bayes
python main.py --criterion wald
python main.py --criterion all
python -m unittest -v
python make_report.py
```

`all` рассчитывает оба критерия. Для PDF нужен Microsoft Edge, как в предыдущих работах.
Формулы и диаграмма в HTML работают без интернета.

Независимая проверка (не обязательна для обычного запуска):

```
python -m pip install -r requirements-check.txt
python verify.py
```

`verify.py` строит другую модель: смешанную целочисленную задачу на дереве сценариев
и решает её через `scipy.optimize.milp`. Основной метод лабораторной реализован в
`portfolio.py`, MILP используется только для проверки оптимума.
Оба результата совпали с Беллманом с разностью менее `1e-9` д.е., разрыв MILP равен нулю.
